Fixes #1273. This is the change @virtualtam proposed there.

`quality.yml` had no concurrency group, so an older run on a PR kept going through its whole Windows and Linux matrix after a newer push. That was about 300 runner-minutes a week by the issue's count.
- The group is keyed on the PR number, not `head_ref`, because fork PRs often share a branch name like `patch-1`.
- When `release.yml` calls the workflow (a push context) or it's dispatched by hand, there's no PR number. The group is then the run's own id: those runs are never cancelled and never collide with `release.yml`'s `release-<ref>` group.
